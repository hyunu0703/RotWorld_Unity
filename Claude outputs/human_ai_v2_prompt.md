# 작업 지시: 인간 AI v2 (생존 판단·정착·파밍·건물 출입)

## 작업 전 필수
- 저장소: `RotWorld_Unity` (Unity 프로젝트 `RotWorld/`, 스크립트 `RotWorld/Assets/Scripts/`)
- `CLAUDE.md`, `AGENTS.md`, `Md/Unity_CSharp_Coding_Rules.md`를 먼저 읽고 따른다
  - `.cs`는 UTF-8(BOM 없음), 주석은 짧은 구 형태·마침표 없음, 함수 사이 빈 줄 2개, 필드 용도별 그룹 주석
  - 요청과 무관한 코드 변경, 중복 구현 금지. 기존 시스템 재사용 우선
- 프로젝트 문서 `claude/human-ai-v2-spec-review.md`(최종 기획), `claude/item-placement-v1.md`(재고·수치 근거) 참고
- 현재 AI 구조: 인간·좀비 이동·판단 전부 `UnitWander.cs`(약 2,500줄). 감지 `UnitSight.cs`, 경로 `UnitPathfinder.cs`, 전투 `UnitCombat.cs`, 수치 `HumanNeeds.cs`, 소지품 `HumanInventory.cs`, 지도 데이터 `CityMap`/`CityBuilding`(`CityGenerator.cs`), 건물 종류 `BuildingCatalog.cs`, 건물 이름 패널 `BuildingInfoPanel.cs`, 지도 표시 `CityMapView.cs`
- `UnitWander`가 이미 크므로 새 판단 로직은 별도 클래스로 분리하고 `UnitWander`에는 연결 지점만 추가

## 시간·수치 기준
- 현실 1초 = 게임 1분 (`GameClock`). 게임 12시간 = 현실 12분, 게임 30분 = 현실 30초
- 허기 100→0 7일, 갈증 100→0 3일, 최대 150 (`HumanNeeds`)
- 소지 5칸, 가방 착용 15칸. 재고 `CityBuilding.Stock`은 `ItemCatalog.All` 순서 7칸(비스킷·빵·통조림·전투식량·생수·주스·가방)

## 판단 우선순위 (기존 감지 주기 0.2초마다)
1. 좀비 회피·도주 (최상위)
2. 아사 방지: 섭취·파밍
3. 정착: 머무르기·귀환·이주

## 구현 항목

### 1. 회복 버그 수정 (`HumanNeeds`)
- 문제: `Timeline.Restore`가 0 이후 계속 쌓인 경과 시간에서 회복량을 빼서, 0으로 오래 있을수록 회복량이 줄어듦 (갈증 0으로 12시간 뒤 생수 40 → 약 23)
- 수정: 회복 적용 전 `Elapsed`를 `HungerDuration`, `ThirstElapsed`를 `ThirstDuration` 이하로 고정한 뒤 회복량 차감
- 공유 `Timeline` 구조(`Schedule.Split`) 유지. 다른 인간 수치에 영향 없게

### 2. 아사 (`HumanNeeds`, `UnitWander`, `CityMap`)
- 각 수치의 0 지속 시간 = 경과 시간 − 고갈 시간(음수면 0). 둘 중 최댓값이 게임 12시간 이상이면 쓰러짐
- 회복한 수치는 1번 수정으로 카운트가 자동 초기화됨. 다시 0이 되면 처음부터
- 0 지속 시간을 읽는 조회 프로퍼티 추가 (조회 함수에서 상태 변경 금지)
- 쓰러짐: 기존 `FallDown`의 정리 흐름(협동 해제, 점유·색인 제거, 추격 좀비에 `ForgetHuman` 통지)을 재사용하되 좀비 변환 대신 5초 뒤 먼지 소멸. 연출은 좀비의 흰색 전환(`UnitDeathVisuals.FadeFrames`)과 `Disintegrate` 재사용
- 건물 안에서 죽으면 건물 인원에서 빼고 사라짐
- `CityMap.HumanCount`가 `ConvertedHumans`만 빼므로 아사자도 빠지도록 수정하고 `NotifyPopulationChanged` 호출

### 3. 감지·반격 (`UnitSight`, `UnitWander`)
- 인간의 좀비 감지 반경 7타일 (새 상수). 좀비의 인간 감지는 5타일 유지. `DetectionRadius`를 공유하는 `FindVisibleZombie`/`FindVisibleHuman` 분리
- 도주 유지·해제는 기존 규칙 유지 (8타일 위협 스캔, 15타일 이격 또는 대상 쓰러짐 시 해제)
- 반격: `TryAttackNearbyZombie`는 붙잡혔을 때(`IsGrabbed`)만 일반 반격. 협동 지원자의 지정 좀비 공격은 유지
- 협동 공격 유지: 1명이 좀비 1마리에게만 쫓길 때 주변 인간 1~2명 지원 (`TryStartCooperativeAttack`, `TryRecruitSecondHelper` 기존 조건)
- 도주 중 숨기: 좀비 반대편(좀비 방향과 90도 이상) 6타일 이내 건물 입구가 있고 입구 3타일 안에 좀비가 없으면 그 입구로 도주해 진입

### 4. 주거 분류 (`BuildingCatalog`)
- 주거 시설 판정 조회 추가: 단독주택, 빌라, 시골집, 아파트, 강변 주택, 직원 기숙사, 산장
- 정원 제한 없음

### 5. 건물 출입·인원 집계 (신규 클래스 + `CityMap` + `UnitWander`)
- 건물별 내부 인간 집합과 인원 수, 인원 변경 이벤트를 관리하는 클래스 신설, `CityMap`이 보유
- 진입 판정: 인간이 `CityBuilding.Door` 타일(살구색 사각형, `CityBuildingArt.PaintGround`에서 그림)에 도달. 표시 위치와 판정 좌표가 일치하는지 코드로 확인 후 구현
- 내부 상태: 스프라이트 숨김, 타일 점유·예약 반환, `HumanPositions`·`HumanSpatialIndex`·`HumanQueries`에서 제거 → 좀비 감지·충돌·공격 대상 제외. 경로·추격 상태 초기화, 협동 이탈(`ReleaseCooperativeAttack`), 진행 중 공격 취소. 추격 좀비에게 상실 통지
- 좀비는 출입 불가(진입 판정 없음). 인간은 자유 출입
- 나가기: 입구 3타일 안에 좀비가 없고 입구 타일에 다른 유닛이 없을 때 입구 타일에 다시 등록·표시
- 내부에서도 수치 감소와 아사 적용
- 선택된 인간이 건물에 들어가면 기존 인간 정보 패널이 숨겨진 유닛을 가리키지 않도록 처리 (`HumanNeedsPanel` 확인)

### 6. 좀비의 건물 인지 (`UnitWander` 좀비 쪽)
- 인간이 좀비에게 쫓기는 중(그 좀비의 추격 대상) 건물에 진입한 경우에만, 그 추격 좀비들이 해당 건물을 기억
- 기억한 좀비: 입구로 이동 → 입구 4타일 안에서 머무르거나 배회
- 해제: 해당 건물 인원이 0명이 되면 일반 배회. 머무는 동안 다른 인간을 감지하면 기존대로 추격(추격 종료 후 건물에 인원이 남아 있으면 다시 입구로)

### 7. 판단 상태 머신 (신규 인간 판단 클래스)
상태 예: 정착지 탐색 / 정착 중(내부) / 섭취·파밍 이동 / 파밍 중(내부) / 귀환 / 입구 유인 / 도주(기존 로직 위임)
- 도주는 다른 모든 상태보다 우선. 도주가 끝나면 이전 목표 재개
- 정착지 선택: 위험 표시가 없는 가장 가까운 주거 시설로 `UnitPathfinder.FindTargetPath`(입구 타일 목표) 이동. 도착 시 건물 시야 범위에 좀비가 있으면 위험 표시 후 다음 후보. 후보가 없으면 기존 배회
- 건물 시야 범위: 건물 `Bounds`에서 5타일까지 (건물 안에서 바깥을 보는 기준)
- 정착 중: 내부에 머무름. 섭취·파밍이 필요할 때만 나감
- 이주: 정착지 시야 범위에 좀비 3마리 이상이면 정착지를 버리고(위험 표시) 좀비 반대 방향의 다른 주거 시설 탐색. 나가기 규칙(5번)이 허용될 때까지 내부 대기
- 입구 유인: 목표 건물 입구 3타일 안 좀비가 1마리일 때
  1. 그 좀비 감지 거리(5타일) 안까지 접근해 쫓기게 만든 뒤 입구 반대쪽으로 일직선 이동
  2. 입구에서 8타일 이상 멀어지면 좀비 기준 원형 이동으로 좀비 반대편까지 이동 (`UpdateCooperativeOrbit`의 원형 이동·장애물 회피 재사용 또는 공용화)
  3. 입구로 이동해 진입. 다시 막히면 1부터 반복, 2회 실패 시 다른 건물 선택
  - 입구 3타일 안 좀비가 2마리 이상이면 유인하지 않고 다른 건물 선택
  - 유인 중 다른 좀비가 추가로 쫓으면 일반 도주로 전환

### 8. 섭취·파밍 (신규 파밍 클래스 + `HumanInventory`)
- 시작: 허기 또는 갈증 40 이하
- 섭취 순서: 소지품 중 더 낮은 수치를 채우는 아이템 → 현재 있는 건물 재고(정착지 포함) → 없으면 파밍 출발
- 대상 아이템: 허기·갈증을 채우는 음식·음료 전부 (`ItemCategory.Food`, `Drink`)
- 재고 기억: 인간별로 들어가 본 건물의 재고 스냅샷만 기억. 후보 = 기억상 대상 아이템이 있는 건물 + 미방문 건물, 가까운 순
- 탐색 반경: 정착지(없으면 현재 위치) 기준 20타일, 후보가 없으면 단계적 확대
- 건물 체류: 1건물당 게임 30분. 체류 끝에 아래 처리
  1. 바로 먹기: 더 낮은 수치부터, 최대 150을 넘겨 낭비하지 않는 범위
  2. 빈 칸만큼 가져가기: 더 낮은 수치를 채우는 아이템 → 다른 음식·음료 → 가방(미착용이면 즉시 착용)
  3. `CityBuilding.Stock` 감소, 기억 스냅샷 갱신
- 종료: 두 수치 80 이상 + 소지품에 허기용·갈증용 각 1개 이상 → 정착지 귀환. 미달이면 다음 후보 건물

### 9. UI (신규 라벨 클래스 + `BuildingInfoPanel` + `CityMapView`)
- 인원 1명 이상 건물 위에 `[인원 수]` 라벨 표시, 0명이면 숨김. 위치는 `CityMapView.GetBuildingVisualTop` 기준, 줌 변경에 맞춰 위치 갱신. 기존 이름 패널과 겹치지 않게 배치
- 라벨은 인원 변경 이벤트로 갱신 (매 프레임 문자열 생성 금지)
- 건물 클릭 패널 텍스트: `건물 이름 [인원 수]` (0명 포함). 현재 `BuildingInfoPanel.RefreshName`은 선택 시 한 번만 갱신하므로 인원 변경 시에도 갱신

## 성능 기준
- 건물 후보 검색은 판단 시점에만 수행 (매 프레임 금지)
- 반복 경로에서 LINQ·임시 컬렉션 할당 금지, 재사용 목록 사용
- 경로 탐색은 목표가 바뀔 때만 재계산

## 검증
- Unity 에디터 실행은 불가할 수 있음. 가능한 범위에서 `mcs` 등으로 수정 파일 구문·컴파일 확인
- 수치 계산(회복 버그, 아사 12시간 카운트, 파밍 우선순위)은 단독 테스트 코드로 확인
- 실행하지 않은 검증은 "미검증"으로 명시
