# 작업 지시: 주거 정원·인원별 비축 목표·거점(영역·인원 표시)

## 작업 전 필수
- 저장소: `RotWorld_Unity` (Unity 프로젝트 `RotWorld/`, 스크립트 `RotWorld/Assets/Scripts/`)
- `CLAUDE.md`, `AGENTS.md`, `Md/Unity_CSharp_Coding_Rules.md`를 먼저 읽고 따른다
  - `.cs`는 UTF-8(BOM 없음), 주석은 짧은 구 형태·마침표 없음, 함수 사이 빈 줄 2개, 필드 용도별 그룹 주석
  - 요청과 무관한 코드 변경, 중복 구현 금지. 기존 시스템 재사용 우선
- 프로젝트 문서 `claude/housing-capacity-v1.md`(정원·비축 목표 확정 기획) 참고
- 관련 파일
  - 건물 데이터: `CityGenerator.cs`(`CityBuilding`: `StorageCapacity`, `SettlerCount`, 정착 증감 메서드), `BuildingCatalog.cs`(`IsResidential`, `GetStorageCapacity`, 종류별 저장 상수, `GetName`), `CityLayout.cs`(`GetSizeRange`, 용량 배정 `GetStorageCapacity`)
  - 판단: `HumanBrain.cs`(`SelectTarget`, `FindShelter`, `OnEntered`, `SetSettlement`), `HumanForaging.cs`(`ReservePerSettlerRatio`, `GetReserveTarget`, `HasEnoughReserve`)
  - 표시: `CityMapView.cs`(줌 단계, `ZoomProgress`, `GetBuildingVisualTop`, 정렬 순서 `MapSortingOrder`), `BuildingOccupancyLabels.cs`(건물 안 인원 라벨), `BuildingInfoPanel.cs`(건물 이름·보관 패널), `CityPrototype.cs`(UI 생성·매 프레임 `Refresh` 호출)

## 참고: WorldBox 마을(Village) 표시 조사
- 마을은 8×8 타일 구역(zone) 단위 영역. 처음 3×3 구역으로 시작하고 지도자가 영역을 넓힘
- 새 마을 파견 조건에 인구 기준이 있음 (성인 30명 이상인 마을에서 6~12명을 보내 새 마을 건설)
- 지도 레이어: 마을·왕국 레이어를 켜면 영역을 소속 색으로 칠하고, "Map Names" 옵션으로 영역 이름 표시. 지도자·군대 등은 축소 상태에서도 아이콘으로 표시
- 화면 표현(일반적으로 알려진 모습, 위키에 수치 없음): 영역 안은 소속 색 반투명 채움, 경계는 같은 색의 진한 외곽선, 영역 위에 `이름 + 인구 수` 이름표. 지도를 끝까지 축소해도 영역과 이름표가 유지됨
- 이 프로젝트 적용: 구역 격자 대신 **건물 영역 + 건물 시야 5타일** 사각형, 마을 대신 **정착 인원 6명 이상 주거 시설 = 거점**

## 구현 항목

### 1. 주거 정원 (`BuildingCatalog`, `CityBuilding`, `CityLayout`)
- 정원 = 정착 인원(`SettlerCount`) 상한. 건물 안 인원(`BuildingOccupancy`)은 제한하지 않음
- 정원 = 기본 정원 × 필지 크기 보정, `Mathf.RoundToInt`, 최소 1. 주거 시설 외 0

  | 주거 시설 | 기본 정원 | 정원 범위 |
  |---|---:|---:|
  | 산장 | 2 | 2 (고정 규격, 보정 1.0) |
  | 시골집 | 3 | 2~4 |
  | 단독주택 | 4 | 3~5 |
  | 강변 주택 | 4 | 3~5 |
  | 빌라 | 6 | 4~8 |
  | 직원 기숙사 | 10 | 8~12 |
  | 아파트 | 12 | 9~15 |

- 필지 보정(0.75 + 0.5 × t)은 `GetStorageCapacity`의 계산을 공용 함수로 분리해 저장 용량과 함께 사용 (식·상수 중복 금지). 지역 면적 범위는 `CityLayout.GetSizeRange` 그대로
- 생성 시 한 번 계산해 `CityBuilding`에 읽기 전용 보관 (`StorageCapacity`와 같은 경로, 복사 생성자 포함)
- 정원 조회 `IsFull` 같은 조회 프로퍼티 추가 (조회 함수에서 상태 변경 금지)

### 2. 정원 반영 행동 (`HumanBrain`)
- `FindShelter`: 만원(`SettlerCount >= 정원`) 건물 제외, 다음으로 가까운 주거 시설
- 입구 도착 시 재확인: 만원이면 진입은 허용하되 정착 확정 안 함 → 목표 해제 후 다음 검색. 위험 표시(`MarkDanger`) 하지 않음
- 만원 건물은 영구 제외하지 않음. 다음 검색 주기에 다시 판단
- 모든 주거 시설이 만원·위험이면 기존 실패 처리(`SearchRetryInterval` 재검색) 유지
- 도주 중 숨기·파밍 방문은 정원 무관

### 3. 인원별 비축 목표 (`HumanForaging`, `BuildingCatalog`)
- 기존 `min(용량, 올림(용량 × 50%) × 정착 인원)` 대체
- 비축 비율 = min(100%, 50% + 추가 비율 × (정착 인원 − 1)). 비축 목표 = 올림(저장 용량 × 비축 비율). 정착 인원 0이면 0

  | 주거 시설 | 추가 1명당 |
  |---|---:|
  | 산장 | 25% |
  | 시골집 | 25% |
  | 단독주택 | 20% |
  | 강변 주택 | 20% |
  | 빌라 | 15% |
  | 직원 기숙사 | 10% |
  | 아파트 | 10% |

- 추가 비율은 `BuildingCatalog`에 저장 상수와 같은 방식(종류별 상수 + switch 조회)으로 추가. 1명 기준 50%는 `HumanForaging`의 기존 상수 재사용·이름 정리
- 부동소수 오차로 올림 결과가 1 커지지 않게 정수 백분율로 계산 (예: 용량 × 퍼센트 + 99) / 100
- 출발·귀환·저장 조건은 기존 유지 (`HasEnoughReserve`만 새 목표 사용)

### 4. 거점 판정 (신규 클래스, `CityMap` 보유)
- 거점 = 주거 시설 중 정착 인원 **6명 이상**. 6 미만이 되면 해제 (이주·아사·변환·제거로 감소 시)
- 정착 인원 변경 시 `CityBuilding`에서 지도 단위 변경 번호(버전) 증가 → 거점 목록은 버전이 바뀔 때만 재구성 (`BuildingOccupancy.Version` 방식 참고). 매 프레임 전체 건물 순회 금지
- 거점 영역 = 건물 `Bounds`를 사방 5타일 확장한 사각형, 지도 범위로 잘라냄. 5타일은 `HumanBrain`의 건물 시야 상수를 공유 (중복 정의 금지)
- 거점 색: 생성 시 한 번 랜덤 RGB 선택 후 거점이 유지되는 동안 고정
  - 채도·명도를 일정 이상으로 두어 지형과 구분되는 선명한 색 (예: `Color.HSVToRGB(랜덤 색상, 0.7~0.9, 0.85~1)`)
  - 지도 시드 기반 전용 난수 사용 (`UnityEngine.Random` 전역 상태 변경 금지)
  - 해제 후 다시 6명이 되면 새 색 배정 가능
- 범위 상수: 거점 기준 인원 6, 영역 여백 5, 채움 알파, 외곽선 알파는 한곳에 상수로

### 5. 거점 영역 표시 (`CityMapView` 또는 신규 렌더러)
- 지도 좌표(타일 단위) 기반 월드 공간 표시. 기존 지도와 같은 `mapView.transform` 아래
- 채움: 거점 색, **투명도 높음** (알파 약 0.2~0.25)
- 외곽선: 같은 색, **투명도 낮음** (알파 약 0.9). 줌과 관계없이 화면상 일정 두께(예: 2px)로 보이도록 줌 변경 시 두께 갱신 또는 화면 픽셀 기준 계산
- 정렬: 지형·건물 위, 유닛 아래 (`MapSortingOrder` 기준, `UnitWalkAnimation.LivingSortingOffset`보다 낮게)
- **모든 줌 단계(전체 보기·추가 축소 단계 포함)에서 표시**
- 겹치는 거점은 각각 그림 (병합 불필요)
- 메쉬는 거점 목록이 바뀔 때만 재생성. 줌·이동 시 재생성 금지 (두께 갱신만 허용)

### 6. 거점 인원 텍스트 (`BuildingOccupancyLabels` 확장 또는 신규 라벨 클래스)
- 표시: `건물 이름 [정착 인원]` (이름은 `BuildingCatalog.GetName`)
- 위치: 거점 영역 상단 중앙 바로 위 (영역 기준이므로 축소해도 영역과 함께 보임)
- **축소해도 항상 표시**. 기존 라벨처럼 `ZoomProgress`로 축소하되 최소 배율을 따로 두어 최소 줌에서도 읽을 수 있게 함
- 라벨 배경 또는 글자 외곽에 거점 색을 넣어 영역과 연결
- 같은 건물의 건물 안 인원 라벨(`[n]`)과 겹치지 않게: 거점 건물은 거점 라벨만 표시하거나, 건물 안 인원을 함께 표기 (예: `빌라 [7]` 아래 기존 라벨 숨김). 선택한 건물은 기존처럼 이름 패널과 겹치지 않게 처리
- 문자열은 정착 인원이 바뀔 때만 갱신 (매 프레임 문자열 생성 금지). 위치만 매 프레임 갱신
- UI 생성은 `CityPrototype`의 기존 라벨 생성 흐름(템플릿 복제) 재사용

### 7. 건물 패널 (`BuildingInfoPanel`)
- 주거 시설 패널에 `정착 n / 정원` 줄을 `보관 n / 용량` 줄 위에 추가. 정착 인원 변경 시 즉시 갱신

## 성능 기준
- 거점 판정·메쉬 생성은 정착 인원 변경 시에만 수행
- 반복 경로에서 LINQ·임시 컬렉션 할당 금지, 재사용 목록 사용
- 정원·용량 계산은 생성 시 한 번

## 검증
- Unity 에디터 실행은 불가할 수 있음. 가능한 범위에서 `mcs` 등으로 수정 파일 구문·컴파일 확인
- 단독 테스트 코드로 확인
  - 정원: 종류별 최소·최대 필지에서 기본 정원 × 0.75 / × 1.25 반올림 (빌라 4·8, 아파트 9·15, 산장 2)
  - 비축 목표 (기본 용량 기준): 산장 8·12, 시골집 10·15·20, 단독주택 13·18·23·25, 빌라 15·20·24·29·30, 기숙사·아파트 1~6명 50~100% (20·24·28·32·36·40 / 25·30·35·40·45·50)
  - 만원 건물 제외, 만원 도착 시 정착 미확정·위험 미표시
  - 거점: 5명 → 6명 생성, 6명 → 5명 해제, 영역 = Bounds + 5 지도 범위 제한, 색 알파(채움 낮은 불투명도·외곽선 높은 불투명도)
- 실행하지 않은 검증은 "미검증"으로 명시
